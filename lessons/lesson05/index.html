01

API 連携とは

API とは、他のプログラムやサービスの機能を、決められた形式の要求を送って使う仕組みです。要求の送り先（URL）、送る内容の形、返ってくる内容の形があらかじめ決まっていて、その決まりに従って送れば、相手のプログラムを自分のアプリから動かせます。API 連携は、自分のアプリの中から外部サービスの API を呼び出して、その結果を自分の画面に使うことです。

用語

API
Application Programming Interface の頭文字。プログラムから別のプログラムやサービスの機能を呼び出すための、決められた呼び出し方。送り先の URL、送る内容の形、返る内容の形が決まっています。
リクエスト／レスポンス
リクエストは API に送る要求。レスポンスはそれに対して返ってくる答え。API の呼び出しは、この1往復で成り立ちます。
URL
インターネット上の場所を表す文字列。ブラウザのアドレス欄に入れるものと同じです。API では「どこに要求を送るか」を表します。
JSON
データを決まった書き方の文字で表す形式。項目名と値の組を { "amount": 500, "memo": "昼食" } のように書きます。API のリクエストとレスポンスの多くはこの形です。

ふだん使っているアプリも、裏では API を呼んでいます。たとえば、天気アプリは気象情報のサービスの API から今日の予報を受け取って表示し、地図アプリは経路検索の API に出発地と目的地を送って経路を受け取っています。AI 機能も同じ形で、自分のアプリから AI のサービスの API に文章を送り、生成された文章を受け取って画面に出します。

API 連携をするときの形（この回でいちばん大事なこと）

自分のアプリから AI のサービスを呼ぶときは、画面（ブラウザ）から直接呼ばず、自分のサーバーを経由します。

用語

画面側（フロントエンド）
ブラウザの中で動く部分。HTML／CSS／JavaScript でできていて、その中身は開発者ツールで誰でも見られます。
サーバー側（バックエンド）
利用者から見えない場所で動く部分。自分の PC で node server.js のように起動しているプログラムがこれに当たります。秘密の文字列を使う処理や、ファイルの読み書きはここで行います。
開発者ツール
ブラウザに標準で付いている、画面の中身や通信の内容やエラーを調べる機能。Chrome では F12（Mac は ⌥⌘I）で開きます。

なぜサーバーを経由するのか

  • AI のサービスを呼ぶには、03 で扱う API キーが要ります。画面側のコードに書くと、開発者ツールで誰でもそのキーを読めます（読まれると何が起きるかは 03 で説明します）
  • サーバー側に置いたキーは、画面に返す内容やエラー表示に含めなければ、ブラウザからは見えません。キーを使う処理は、必ず見えない場所に置きます
  • 自分のサーバーを間にはさんでおくと、あとで AI のサービスを別のものに変えるときも、画面側は一切直さずに済みます

選ぶときに見る4つの観点

費用
見るところ無料で試せる範囲があるか。先にクレジットを買う前払いか。無料枠で送った内容がサービスの改善に使われるか（Gemini の無料枠は使われます。05 の「AI に送ってよい情報の実物確認」）
なぜ作っている途中で何度も呼びます。試す段階で費用がかかると手が止まります
扱える入力
見るところ文章だけか、画像や PDF も渡せるか
なぜ変換型で「写真から読み取る」ような機能を考えているなら、ここで決まります
上限設定
見るところ管理画面に「月にここまで」という上限を置けるか。超えたときに止まるのか、通知だけか
なぜ作りを間違えて何度も呼ばれたとき、被害を金額で止められます
日本語の出力
見るところ自分の用途の文章が自然に返ってくるか
なぜ要約や言い換えは、日本語の品質がそのまま使いやすさになります

用語

モデル
呼び出す AI の種類。同じサービスの中に、速いもの・賢いもの・安いものなど複数あり、名前を指定して呼び分けます。名前は変わることがあるので、公式ページで確認します。
トークン
AI のサービスが文章を数える単位。送った文章と返ってきた文章の両方がトークンで数えられ、料金はその数で決まります。日本語は1文字が1トークン以上になることが多いです。
無料枠
契約直後や一定量までは無料で使える範囲。あるかどうか、どこまでかはサービスごとに違い、変わることがあります。
上限設定
サービスの管理画面で「月あたりここまで」と決めておく設定。超えたときに呼び出しが止まるか、通知だけかは、サービスと設定で違います。設定した画面で確かめます。
レート制限
短い時間に送れる要求の回数の上限。1分あたり・1日あたりのように決まっていて、超えると一時的にエラーになります。無料枠では少なく設定されています。
前払い（クレジット）
先に金額を入れておき（この金額をクレジットと呼びます）、その範囲で使う方式。残高が少なくなると自動で買い足す設定（自動リロード）をオフにしておけば、残高が尽きたところで呼び出しが止まります。

なぜ推奨を置かないのか：料金も無料枠も短い期間で変わります。1社を推奨として固定すると、条件が変わったときに全員が不利な選択をしたままになります。観点を渡して、その時点でご自身に合うものを選べる状態にしておきます。

選んだサービスは、この回の課題を出すときに一緒に書いてください。同じサービスの環境で見ないと、詰まったときに再現できず、講評ができません。迷ったら、ゼミで使っている Claude と同じ提供元の Claude API にすると、ログインするアカウントを1つにできます（ただし Claude の月額プランと API の支払いは別です）。

03

API キー：パスワードと同じ扱いをする

API キーは、そのサービスに「自分として」アクセスするための長い文字列です。これを付けて要求を送ると、サービスは「この人からの要求」と判断し、使った分をその人に請求します。

用語

API キー
サービスが発行する、本人確認のための長い文字列。sk-ant-…（Claude）、sk-…（OpenAI）、AQ.…（Gemini。以前に作られたキーは AIza…）のような決まった文字で始まることが多いです（形式は変わることがあります）。
.env
API キーのような秘密の文字列を書いておくファイル。アプリのフォルダの直下に置きます。名前は「環境（environment）」の略です。
環境変数
プログラムの外側から渡す設定値。.env に書いた内容は、起動時に環境変数として読み込まれ、サーバー側のプログラムから process.env.ANTHROPIC_API_KEY のような名前で取り出せます。
.gitignore
共有の場所に上げないファイルの名前を書いておく一覧。ここに .env を書いておくと、コードを共有するときに .env だけが除かれます。
node_modules
アプリが使う部品（ライブラリ）を入れるフォルダ。部品を入れる命令を打つと自動で作られ、中身はとても多くなります。部品の一覧があればいつでも作り直せるので、共有や提出には含めません。
絶対にやってはいけないこと（3つ）
① 画面側のコード（HTML や JavaScript）に書く
② GitHub などコードを共有する場所に上げる
③ スクリーンショットに写ったまま提出する・掲示板に貼る

なぜ画面側に書いてはいけないのか：ブラウザで動くコードは、開発者ツールを開けば誰でも読めます。キーが読まれると、他人がご自身の請求でそのサービスを使い放題になります。キーは「使うと請求が来るパスワード」であって、設定値ではありません。

なぜスクリーンショットまで気にするのか：管理画面でキーを作った直後の画面や、.env を開いた画面をそのまま撮ると、キーの全文が写ります。掲示板や提出物に貼った時点で、見た人全員がそのキーを使えます。

キーが写ってしまったときの対処：まだどこにも貼っていなければ、キーが写らない範囲で撮り直します。一度でも掲示板・提出フォーム・共有の場所に出したら、貼り直すのではなく、管理画面でそのキーを無効化して作り直します。なぜ出したら作り直すのか：貼った画像を消しても、消すまでの間に見た人や、画像を保存した人の手元にはキーが残ります。無効化すれば、そのキーで送られた要求はすべて断られます。

.env の開き方：名前が . で始まるファイルは、ふだんは隠れていて見えません。

  • Windows：.env を「メモ帳」で開いてキーを貼り、保存します。「名前を付けて保存」になったときは、「ファイルの種類」を「すべてのファイル」にしてから、名前を .env のまま保存します。なぜ：「テキスト文書」のまま保存すると .env.txt という名前になり、プログラムが読みません

04

各サービスでキーを発行する

3つとも「ログイン → API キーの画面 → 作成 → 表示されたキーをその場で .env に貼る」の流れです。キーは作った直後にしか全文が表示されないサービスが多いです。画面を閉じる前に .env に貼り、貼れたことを確認してから閉じます。選んだサービスの節だけ読めば足ります。

支払い方法の登録を求められることがあります。登録するときは、選んだサービスの節にある上限の設定まで一緒に済ませます。登録だけして上限を置かないまま作り始めないでください。上限を置く画面と、超えたときに止まるかどうかは、3つのサービスでそれぞれ違います。

4-1. Claude API（Anthropic）

  1. 1

    platform.claude.com（Claude Platform。旧 Claude Console）を開き、Google アカウントかメールアドレスでログインする

    なぜ：API キーはアカウントに紐づきます。ゼミで使っている Claude と同じアカウントでログインできます。ただし Claude の有料プラン（Pro など）に API の利用は含まれず、API は Claude Platform の「請求」で別にクレジットを買います。

  2. 2

    「使用クレジットを購入して開始する」が出たら、ここでは買わず「今はスキップ」

    なぜ：AI を呼ぶまでは費用はかからないため、買うのは経路が通ってからにします。左のメニュー「組織の設定」→「API キー」を開きます。

  3. 3

    「キーを作成」を押し、名前と有効期限を決めて「キーを作成」

    途中で「ID 連携を使用すれば、API キーは不要です」という案内が出たら「API キーで続ける」を選びます（ID 連携はクラウド上で動かす場合の仕組みで、ご自身の PC で動かすアプリには使いません）。キーの全文が1回だけ表示されるので、その場で .env に貼ります。

  4. 4

    （5-2 の手順3 で「テスト応答です」が出たら）「請求」の画面でクレジットを購入し、自動リロードはオフのまま、「Spend limits」で月の上限を置く

    Claude API は前払いで、買ったクレジットの範囲で使います。最初は少額で十分です。購入のときに「自動リロード（Auto-reload）」を入れる欄があれば、オフのままにします。なぜ：自動リロードを入れると、残高が減るたびに自動で買い足され、残高が上限の役目をしなくなります。
    あわせて、同じ「請求」の画面の「Spend limits」で「Set limit」（設定済みなら「Adjust limit」）を押し、月の上限額を入れます。なぜ両方か：月の上限に達すると、その月の呼び出しはエラーで止まります。残高と月の上限の2つで止めておけば、どちらかの設定を変えたときにも使いすぎを防げます。金額の選択肢と画面の文言は変わることがあります。

4-2. OpenAI API（OpenAI）

  1. 1

    platform.openai.com を開き、ログインする

    ChatGPT を使っているアカウントでログインできますが、ChatGPT の有料プランと API の契約は別で、API は先にクレジットを買い、その残高から使った分が引かれます。なぜ確認するのか：ChatGPT の月額を払っていれば API も使えると思って作り始め、残高が無いというエラーで止まる人が多いためです。

  2. 2

    左のメニュー「API Keys」→ 右上の「Create new secret key」

    名前を付け、Permissions は「All」のまま「Create secret key」を押します。なぜ All か：「Restricted」を選ぶと使える機能を絞れますが、AI を呼ぶ権限を付け忘れると、正しいキーでもエラーになります。まずは All で動かします。キーの全文が1回だけ表示されるので、その場で .env に貼ります。

  3. 3

    「Settings」→「Billing」で支払い方法を登録し、クレジットを買う

    画面に「API credits are separate from ChatGPT」（API のクレジットは ChatGPT とは別）と書いてあるとおり、ChatGPT の契約とは別に、ここで API 用の残高を入れます。なぜ：残高が 0 のままでは、キーが正しくても API を呼べません。最初は少額で十分です。

  4. 4

    「Settings」→「Limits」（Billing の「Usage limits」からも開けます）の「Spend」で「Edit spend limit」を押し、月の上限額を入れて「Enforce a hard limit」をオンにして保存する

    支払いを登録してクレジットを買うと、「Limits」の画面に上限の欄（Spend）が出ます。登録前の画面には、購入額に応じた段階（Usage Tiers）と、1分あたりに送れる回数（レート制限）だけが出ています。なぜ「Enforce a hard limit」までオンにするのか：オフのままだと、上限額に達してもメールが来るだけで呼び出しは止まりません。オンにすると、上限を超えたあとの呼び出しがエラーで止まります。止まるまで少し遅れることがあり、記録上の金額がわずかに上限を超えることがあります。画面の文言は変わることがあります。

4-3. Gemini API（Google）

  1. 1

    aistudio.google.com を開き、Google アカウントでログインする

    左のメニューに「API キー」があります。

  2. 2

    右上の「API キーを作成」を押し、名前とプロジェクトを決めて「キーを作成」

05

AI 機能を入れる：経路を先に通してから、中身を差し替える

ここでやるのは「自分のアプリのサーバー側から AI のサービスに文章を送り、返ってきた文章を画面に出す」ことです。次の順番を崩さないでください。最初に、いまの画面をサーバーから開けるようにして土台を作り（5-1）、そのうえで経路を通して AI に差し替えます（5-2）。画面の中だけで動く動き（ボタンを押すと一覧や結果の欄が変わる部分）は、もうできている前提で進めます（まだ無い場合は、5-1 の最後で1つ足します）。

5-1. まず、いまの画面をサーバーから開けるようにする

作る順番の一覧 docs/tasks.md がある場合、画面の中だけでできるタスク（例：「1件保存して一覧に出す（読み込み直すと消えてよい）」「入力の間違いを弾く」）は、動きの一覧 docs/actions.md でその動きが「作った」になっていれば、もう終わっています。06（データの持ち方）は、「消えずに残るようにする」のような、データを残すタスクに当たります。tasks.md の順番と見比べて、終わったタスクには Claude Code に終わった印（- [x]）を付けさせます。なぜ：印が実物とずれていると、次に作り始めるときに、できているものをもう一度作らせることになります。

いまのアプリは、app/ の中の HTML と CSS に、画面の中だけで動く JavaScript（例：app/app.js。AI を使うアプリは、仮の文章を返す app/ai.js も）が付いた状態です。ボタンを押すと画面は変わりますが、データは画面の中に持っているだけで、外のサービスにはつながっていません。AI のサービスを呼ぶには、次の2つが要ります。

  1. 自分のサーバーへ要求を送り、返ってきた答えを画面に出す部分（画面側の JavaScript。いまの動きに足す）
  2. その要求を受け取って、外部のサービスを呼ぶ部分（サーバー側のプログラム）

この 5-1 では、まずサーバーを立てて、いまの画面をサーバーから開けるようにします。要求を送る部分は 5-2 で足します。

アプリは「見た目 → 動き → 裏側」の順に1段ずつ足して作ります。見た目と、画面の中だけで動く動きができていれば、ここで足すのは裏側だけです。なぜ1段ずつか：一度に全部を作らせると、うまくいかないときに、見た目・動き・裏側のどこが原因か分かりません。1段足すたびに確かめておけば、先に調べるのは最後に足した1段で済みます。

なぜ画面を作り直さないのか：いまある HTML と CSS は、ご自身で見て決めた配置と見た目そのものです。動きがある場合は、それもご自身の手で押して確かめたものです。作り直させると配置も文言も動きも変わり、確かめ直しになります。足すのはサーバーと、画面からサーバーを呼ぶ処理だけで、画面のファイルは土台としてそのまま使います。

仕様書の「使う技術」で、HTML をそのまま使わない構成（React など）を選んだ場合は、いまの画面の配置・文言・色・余白を変えずに、その構成の書き方へ移させます。

データの持ち方：4つの置き場と、消える条件

ここまでのアプリは、データを画面の中に持っているだけで、再読み込みすると消えます。動きの一覧 docs/actions.md で「あとで」にした行のうち、データを残す・画面をまたいで渡す行（修正画面に選んだ記録を出す・閉じても残る など）は、置き場を決めたあとに1行ずつ作ります（なぜ：残し方は置き場によって変わるため、決める前に作ると作り直しになります）。AI 機能が動いたら、次は「このデータをどこに置いておくか」をご自身で決めます。置き場によって、消える条件と、どこから見えるかと、設定の手間が違います。

app.js に「見本のデータ」がある場合（画面の中だけで動く動きを作ってある場合）は、このあとの置き場の指示を送るとき、型の最後に次の1行を足してください。「app.js の見本のデータは外して、残したデータだけを一覧に出してください。1件も無いときは、いまの案内を出してください」 なぜ：見本のデータは、見た目を確かめるために入れた架空の記録です。残したまま置き場につなぐと、架空の記録が本物の記録と一緒に並んで合計にも入り、1件も無いときの案内も出なくなります。

用語

消える条件
その置き場に入れたデータが無くなる操作や状況。置き場を選ぶときの最初の観点です。
永続化
ブラウザを閉じても、PC を再起動しても残るように保存すること。「画面の中に持っている」状態は永続化されていません。
置き場は、6-5 の選び方で1つに決めてから、その置き場の指示の型を1つだけ送ります。4つ全部は送りません。6-1〜6-4 は、それぞれの置き場の仕組みと消える条件を読んで比べるための説明です。なぜ1つだけか：続けて送ると、保存の処理が置き場の数だけ作られ、記録がどこに保存されているのか分からなくなります。

6-1. ブラウザの中に持つ（localStorage）

ブラウザには、サイトごとに小さなデータを保存しておく領域があり、その1つが localStorage です。JavaScript から「名前」と「文字列」の組で読み書きでき、ブラウザを閉じても残ります。サーバーが無くても動くので、画面側だけで完結します。

用語

localStorage
ブラウザがサイト（アドレスの http://localhost:3000 の部分。ポート番号まで含む）ごとに持っている保存領域。名前と文字列の組を保存します。容量は数 MB 程度で、同じ PC の同じブラウザで、同じアドレスから開いたときだけ読めます。
キャッシュ
表示を速くするために、ブラウザが画像やファイルの写しを一時的に持っておく仕組み。いつ消されてもよい前提のものなので、データの保存には使いません。localStorage はキャッシュとは別の領域で、ふつうは利用者が消すまで残ります。ただし PC の空き容量が足りないときや、Safari で7日ほどそのページを開かなかったときは、ブラウザが消すことがあります。
どこにあるか
自分の PC の、そのブラウザの中
消える条件
ブラウザの「閲覧履歴データの削除」でサイトデータを消したとき／PC の空き容量が足りなくなり、ブラウザが古いサイトのデータを消したとき／Safari で7日ほどそのページを開かなかったとき。別のブラウザ・別の PC・シークレットウィンドウでは最初から見えません。アドレスのポート番号が変わったとき（:3000 が :5173 になったなど）・公開して別のアドレスで開いたときも、前のデータは見えません
設定の手間
ゼロ。Claude Code に「localStorage に保存して」と言えば動きます
向いている場面
試作／表示の設定（並び順・テーマ）／PC 1台・ブラウザ1つで自分だけが使う小さな記録
ダブルクリックで開いていた画面で残したデータは、サーバーから開いた画面からは見えません。ダブルクリックで開いていたとき（アドレスが file:// で始まる）にブラウザの中へデータを残していても、サーバーから開いた画面（http://localhost:3000 など）には出てきません。なぜ：ブラウザは、アドレスの始まり（file:// か http://localhost:3000 か。ポート番号まで含む）ごとに、別の置き場として扱うためです。ポート番号を変えたとき（:3000 が :5173 になったなど）も同じで、前のアドレスで残したデータは見えません。データは消えたのではなく、前のアドレスの置き場に残っています。

なぜ本番の記録には向かないのか：「履歴を削除」の操作で、貯めた記録がまとめて消えます。使う人はそれが記録の削除だとは思っていません。また、スマホから見たいと思ったときに、PC のブラウザの中にあるデータは取り出せません。

記録の保存先を localStorage にしてください。
保存する項目は docs/spec.md の「扱うデータ」のとおりです。
保存・読み出しの処理は、画面側の1つのファイル（例：app/storage.js）にまとめてください。
完成条件：記録を1件登録してブラウザを再読み込みしても残っていること。開発者ツールの「アプリケーション」→「ローカルストレージ」に保存した内容が見えること。

6-2. 自分の PC のファイルに持つ（JSON ファイル／SQLite）

サーバー側のプログラムが、アプリのフォルダの中のファイルにデータを読み書きします。ファイルの形は、JSON ファイル1つ（data.json）か、SQLite のファイル1つ（data.db）です。

用語

SQLite
データを1つのファイルに表の形で保存する仕組み。検索や並べ替えを SQL という決まった書き方で頼めます。別のプログラムを起動しておく必要がありません。
SQL
データベースに「この条件の行を取り出して」「この行を書き換えて」と頼むための、決まった書き方の文。
バックアップ
データの写しを別の場所に取っておくこと。ファイルに持っている場合は、そのファイルをコピーするだけで済みます。
デプロイ
作ったアプリを、インターネット上の公開用のサービスに置いて動かすこと。コードを直して置き直すことも、デプロイと呼びます。
どこにあるか
自分の PC の、アプリのフォルダの中（data/ などに置く）
消える条件
そのファイルやフォルダを消したとき／PC が壊れたとき／アプリをインターネット上のサービスに公開した場合、置き直すたびにファイルが初期状態に戻ることが多い
設定の手間
少ない。Node.js の標準機能か、SQLite の部品を1つ入れるだけ
向いている場面
自分の PC だけで使うアプリ／中身をファイルとして開いて確かめたい／バックアップをコピーで済ませたい

なぜ公開すると消えるのか：アプリを動かしてくれる公開用のサービスの多くは、コードを置き直す（デプロイする）たびに、動かす場所をまっさらな状態から作り直します。その中に作ったファイルは、次の置き直しで無くなります。外からも使いたいアプリのデータは、アプリ本体とは別の場所（次の 6-3）に置く必要があります。

JSON ファイルと SQLite のどちらか：件数が少なく項目が単純なら JSON ファイルで足ります。件数が増えて「先月の分だけ」「金額の多い順」のような絞り込みや並べ替えを頻繁にするなら SQLite です。あとで 6-3 のデータベースに移す予定があるなら、最初から SQLite にしておくと、同じ SQL が使えるので、移すときに変える場所が主に接続の部分で済みます。

記録の保存先を、アプリのフォルダ内の SQLite ファイル（data/app.db）にしてください。
保存・読み出しの処理はサーバー側の1つのファイルにまとめ、画面側からは自分のサーバーを呼ぶだけにしてください。
.gitignore に data/ を追加してください。
完成条件：記録を1件登録して、5-1 で起動したサーバーを止めて起動し直しても残っていること。

なぜ data/ を .gitignore に入れるのか：記録の中身はご自身の生活や仕事のデータで、コードと一緒に共有する場所へ上げるものではないからです。

6-3. インターネット上のデータベースに持つ（Turso）

データベースは、データを表の形で保存し、検索・並べ替え・書き換えを専門に担当するプログラムです。Turso は、6-2 で使った SQLite をインターネット上で動かしてくれるサービスで、自分のサーバーからは接続用の URL とトークンを使ってつなぎます。

用語

データベース（DB）
データを表の形で保存し、検索・並べ替え・書き換えを担当する専用のプログラム。アプリ本体とは別の場所に置けます。
Turso
SQLite をインターネット上のサービスとして提供しているもの。手元の SQLite と同じ SQL が使えます。
接続情報
データベースにつなぐための「場所（URL）」と「本人確認のトークン」。API キーと同じく .env に置き、サーバー側からだけ使います。
トークン（Turso）
データベースにつなぐための本人確認の文字列。Turso の管理画面で発行します。02 で出てきた、AI の料金を数える「トークン」とは別のものです。
どこにあるか
Turso のサーバー（自分の PC の外）
消える条件
Turso の管理画面でデータベースを消したとき（消したデータベースは無料プランでは戻せません）／契約が止まったとき。アプリを置き直しても消えません。PC を替えても同じデータを見られます。無料プランでは、しばらく使わないとデータベースが休止し、つながらなくなることがあります（データは残っていて、休止を解けばまた使えます）
設定の手間
中くらい。Turso のアカウント作成 → データベース作成 → 接続情報を .env へ → サーバー側の接続先を変更
向いている場面
アプリを公開してスマホからも使う／PC を替えてもデータを引き継ぐ／件数が増える見込み

なぜ Turso なのか（ほかの選択肢と、なぜ今回それを選ばないか）

  • 手元の SQLite と同じ SQL が使えます。6-2 で SQLite にしておけば、変える場所は主に接続の部分です（使う部品の違いで、少し直しが入ることがあります）。保存・読み出しの処理を一から書き直さずに済みます
  • Supabase や Firebase には、画面側から直接データベースにつなぐ使い方が多くあります。この作りは便利ですが、アクセス制限の設定を1つ誤ると、データが誰からでも読める状態になります。このゼミでは「データベースにつなぐのはサーバー側だけ」という作りに統一し、その形が自然に取れる Turso にします
  • 無料で使える範囲がありますが、内容は変わることがあります。2026年10月2日に、Turso は Supabase に加わると発表しました（サービスは続くと案内されています。料金・無料プラン・画面がいつ変わるかは、2026年10月3日時点で発表されていません）。画面やプランが変わることがあるので、最新は Turso の公式ページでご確認ください

    作ったデータベースの名前を押して「Overview」を開き、「Connect」の枠の接続用 URL（Database URL）をコピーして、.env に TURSO_DATABASE_URL=コピーしたURL の1行を足す

    URL は libsql:// で始まります。.env の開き方は 03 と同じです。なぜ：サーバーがどのデータベースにつなぐかを、この URL で決めるためです。URL だけではつながらないので、次の手順でトークンも作ります。名前（TURSO_DATABASE_URL）は公式の案内に合わせた例です。

6-4. スプレッドシートに持つ（Google スプレッドシート）

データを Google スプレッドシートの表に持ち、サーバー側から Google の API を通して読み書きします。1行が1件、1行目が項目名という形にします。

用語

Google スプレッドシート
Google が提供している、ブラウザで使う表計算のサービス。Excel と同じような表を、インターネット上に持ちます。
サービスアカウント
人ではなくプログラムが Google のサービスを使うための専用アカウント。Google Cloud の管理画面で作り、認証用のファイル（JSON）を受け取ります。このファイルも API キーと同じ扱いで、共有の場所に上げません。
CSV
表の中身をカンマ区切りの文字で書き出したファイル。スプレッドシートや Excel で開けます。
どこにあるか
Google のサーバー（自分の Google ドライブの中）
消える条件
シートを消したとき／サービスアカウントとの共有を外したとき／列の並びや項目名を手で変えたとき（アプリが読めなくなります）
設定の手間
多い。Google Cloud でプロジェクトとサービスアカウントを作る → 認証用のファイルを受け取る → シートをそのアカウントに共有する → サーバー側で API を呼ぶ
向いている場面
一覧を人が眺めて手で直したい／すでにスプレッドシートで管理している作業の続き／家族や同僚と同じ表を見たい

なぜスプレッドシートが選ばれるのか：アプリを作る前からスプレッドシートで管理していた作業なら、これまでの表をそのまま使えます。表を眺めて直すのは、専用の画面を作るより速いです。集計やグラフも、スプレッドシート側の機能で済みます。

なぜ本番のデータベースの代わりにはならないのか

  • 読み書きのたびに Google の API へ通信するので、1回の操作に時間がかかります（体感で分かる程度）
  • 短時間に何度も書き込むと回数の上限に当たります
  • 人が表を直接編集できるのが利点でもあり、列を1つ動かしただけでアプリが読めなくなる弱点でもあります
簡単な代わり：記録の保存先は 6-2 か 6-3 にしておき、「CSV で書き出す」ボタンだけを付けます。書き出した CSV をスプレッドシートに取り込めば、眺める・直す・集計するはスプレッドシートでできます。API の設定が要らないので、まずはこの形で足りるかを考えてみてください。 
記録の保存先を Google スプレッドシートにしてください。
シートの ID は .env の SHEET_ID から、サービスアカウントの認証ファイルの場所は .env の GOOGLE_APPLICATION_CREDENTIALS から読み、サーバー側からだけ使ってください。.env と認証用の JSON ファイルの中身は開いて読まないでください。
認証用の JSON ファイルの名前を .gitignore に追加してください。
1行目を項目名（docs/spec.md の「扱うデータ」の項目名）、2行目以降を1件1行にしてください。
完成条件：アプリで1件登録すると、シートに1行増えること。シートで直した内容がアプリの一覧に反映されること。

なぜ認証用の JSON ファイルを .gitignore に入れるのか：このファイルを持っていれば、誰でもそのサービスアカウントとして、共有したシートを読み書きできるためです。提出する zip にも入れません。

  • 公開して外からも使う、PC を替えても続ける → Turso
  • 表を人が直接眺めて直す、家族と共有する → スプレッドシート（まずは CSV 書き出しで足りないかを考えます）
  • 試作や、並び順のような表示の設定だけ → localStorage
保存の処理は、1つのファイルにまとめておきます。PC のファイル・Turso・スプレッドシートなら、サーバー側の1つのファイルにまとめ、画面側は「自分のサーバーに頼む」だけにします。localStorage なら、画面側の1つのファイル（例：app/storage.js）にまとめます。置き場の違いは、そのファイルの中だけに閉じ込めます。 なぜ：置き場を変えるとき、直す場所が1つで済みます。画面側にまで保存の処理が散らばっていると、置き場を変えるたびにアプリ全体を作り直すことになります。

Pitfalls

よくあるつまずきと対処

詰まったら、Home の「分からないことが出てきたらこの順番で」の順（スクショを撮って AI に聞く → ゼミ掲示板）で進めてください。スクショを撮るときは、キーが写っていないかを先に見ます。

あとからファイルを消しても、上げた記録（履歴）から誰でも読めます。

対処：管理画面でそのキーを無効化して作り直すことだけが対処です。消して上げ直しても、前のキーは読めるままです。作り直したら、.gitignore に .env が入っていることを確かめてから続けます。

対処：いったん「テスト応答です」を返す状態に戻して経路を確かめ、通ってから差し替え直します。

サーバーから開いたら、ボタンを押しても動かない（ダブルクリックで開いていたときは動いた）

入口がすぐに答えを返して一瞬で終わっているか、入口が返したエラーを、関数が失敗として扱っていません。

対処：「サーバー側の入口は、1秒待ってから返すようにしてください」「入口がエラーを返したときは、いまと同じく失敗として扱ってください。ほかは変えないでください」のうち、当てはまるほうを頼みます。サーバーを起動していないと、どの入力でも失敗したときの表示が出ます。そのときは、5-1 で教えてもらった起動のしかたで起動します。

対処：6-2 か 6-3 に移します。保存の処理が1つのファイルにまとまっていれば、直す場所は1つです。

サーバーから開いたら、前に入れたデータが無い

ダブルクリックで開いていたとき（アドレスが file://）と、サーバーから開いた画面（http://localhost:3000 など）では、ブラウザの中のデータの置き場が別です（ポート番号まで含めて、アドレスの始まりごとに分かれます）。データを残す処理をまだ作っていない場合は、再読み込みで最初の状態に戻るのが正しい動きです。

対処：前のアドレスで残したデータは、消えたのではなく、前の置き場に残っています。06 で置き場を決めてから、サーバーから開いた画面で入れ直します（6-1 の注記）。

公開したら記録が消えた

公開先で置き直すたびにファイルが初期化されています。

対処：データはアプリ本体と別の場所（Turso）へ移します。

しばらくぶりに開いたら、Turso につながらない

無料プランでは、しばらく使わないとデータベースが休止します。データは消えていません。

対処：Turso の管理画面でそのデータベースを開き、休止している表示が出ていれば、戻す操作をします。見つからなければ、画面のスクショを撮って AI に聞きます。

スプレッドシートの列を手で動かしてアプリが読めなくなった

一覧が空になる・エラーになります。

対処：1行目の項目名と列の並びは変えません。変えるなら仕様書を直して Claude Code に読み直させます。

社外に出せない情報を AI に送っていた

情報の持ち出しになります。

対処：送る項目を Claude Code に一覧させて確認します。開発中は架空のデータで進めます。Gemini の無料枠では、送った内容が Google の製品の改善に使われます（05 の注意）。

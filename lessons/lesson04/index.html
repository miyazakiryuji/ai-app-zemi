API 連携で AI 機能を入れ、データの持ち方を決める

～ 自分のアプリから AI のサービスを呼び出し、データをどこに置くかを仕組みと消える条件から選ぶ ～

  • Claude デスクトップアプリを使います
  • AI のサービスの契約（Claude／OpenAI／Gemini のどれか）が要ります
  • 成果物：AI 機能が1つ動くアプリ＋上限設定の画面

この回の前に用意しておくもの

画面（見た目）ができている自分のアプリ ＋ Claude デスクトップアプリ ＋ AI のサービスのアカウント

アプリのフォルダ（このページでは例として my-app）の中に、画面（app/）と仕様書（docs/spec.md）がある状態から始めます。 AI のサービスは、このページの「サービスを選ぶ」を読んで1つ決め、アカウントを作っておいてください（キーの発行はこのページの手順で行います）。 支払い方法の登録を求められることがあります。料金と無料で使える範囲は変わることがあるので、契約の前に各サービスの公式ページでご確認ください。

01

API 連携とは

API とは、他のプログラムやサービスの機能を、決められた形式の要求を送って使う仕組みです。要求の送り先（URL）、送る内容の形、返ってくる内容の形があらかじめ決まっていて、その決まりに従って送れば、相手のプログラムを自分のアプリから動かせます。API 連携は、自分のアプリの中から外部サービスの API を呼び出して、その結果を自分の画面に使うことです。

用語

API
Application Programming Interface の頭文字。プログラムから別のプログラムやサービスの機能を呼び出すための、決められた呼び出し方。送り先の URL、送る内容の形、返る内容の形が決まっています。
リクエスト／レスポンス
リクエストは API に送る要求。レスポンスはそれに対して返ってくる答え。API の呼び出しは、この1往復で成り立ちます。
URL
インターネット上の場所を表す文字列。ブラウザのアドレス欄に入れるものと同じです。API では「どこに要求を送るか」を表します。
JSON
データを決まった書き方の文字で表す形式。項目名と値の組を { "amount": 500, "memo": "昼食" } のように書きます。API のリクエストとレスポンスの多くはこの形です。

ふだん使っているアプリも、裏では API を呼んでいます。たとえば、天気アプリは気象情報のサービスの API から今日の予報を受け取って表示し、地図アプリは経路検索の API に出発地と目的地を送って経路を受け取っています。AI 機能も同じ形で、自分のアプリから AI のサービスの API に文章を送り、生成された文章を受け取って画面に出します。

API 連携をするときの形（この回でいちばん大事なこと）

自分のアプリから AI のサービスを呼ぶときは、画面（ブラウザ）から直接呼ばず、自分のサーバーを経由します。

用語

画面側（フロントエンド）
ブラウザの中で動く部分。HTML／CSS／JavaScript でできていて、その中身は開発者ツールで誰でも見られます。
サーバー側（バックエンド）
利用者から見えない場所で動く部分。自分の PC で node server.js のように起動しているプログラムがこれに当たります。秘密の文字列を使う処理や、ファイルの読み書きはここで行います。
開発者ツール
ブラウザに標準で付いている、画面の中身や通信の内容やエラーを調べる機能。Chrome では F12（Mac は ⌥⌘I）で開きます。

なぜサーバーを経由するのか

  • AI のサービスを呼ぶには、次の節で扱う API キーが要ります。画面側のコードに書くと、開発者ツールで誰でもそのキーを読めます。読んだ人は、ご自身の請求でそのサービスを使い放題になります
  • サーバー側に置いたキーは、ブラウザからは見えません。キーを使う処理は、必ず見えない場所に置きます
  • 自分のサーバーを間にはさんでおくと、あとで AI のサービスを別のものに変えるときも、画面側は一切直さずに済みます

02

サービス提供元管理画面の名前開く場所
Claude APIAnthropicClaude Console（Claude Platform）platform.claude.com
OpenAI API（ChatGPT と同じモデルを API で使う）OpenAIOpenAI Platformplatform.openai.com
Gemini APIGoogleGoogle AI Studioaistudio.google.com

表は横にスクロールできます

管理画面の名前・URL・ボタンの文言は変わることがあります。このページの画面と違うときは、「API キー」「Billing（請求）」「Limits（上限）」に相当するものを探してください。料金と無料で使える範囲は短い期間で変わるので、契約の前に、必ず各サービスの公式ページでご確認ください。このページに載せる無料枠の数値は、記載した日に講師のプロジェクトで確かめた例です。自分に当てはまる回数は、Gemini なら AI Studio の「レート制限」で確かめます。

選ぶときに見る4つの観点

費用
見るところ無料で試せる範囲があるか。使った分だけの支払いか、前払いか
なぜ作っている途中で何度も呼びます。試す段階で費用がかかると手が止まります
扱える入力
見るところ文章だけか、画像や PDF も渡せるか
なぜ変換型で「写真から読み取る」ような機能を考えているなら、ここで決まります
上限設定
見るところ管理画面に「月にここまで」という上限を置けるか
なぜ作りを間違えて何度も呼ばれたとき、被害を金額で止められます
日本語の出力
見るところ自分の用途の文章が自然に返ってくるか
なぜ要約や言い換えは、日本語の品質がそのまま使いやすさになります

用語

モデル
呼び出す AI の種類。同じサービスの中に、速いもの・賢いもの・安いものなど複数あり、名前を指定して呼び分けます。名前は変わることがあるので、公式ページで確認します。
トークン
AI のサービスが文章を数える単位。送った文章と返ってきた文章の両方がトークンで数えられ、料金はその数で決まります。日本語は1文字が1トークン以上になることが多いです。
無料枠
契約直後や一定量までは無料で使える範囲。あるかどうか、どこまでかはサービスごとに違い、変わることがあります。
上限設定
サービスの管理画面で「月あたりここまで」と決めておく設定。超えると呼び出しが止まります。

なぜ推奨を置かないのか：料金も無料枠も短い期間で変わります。1社を推奨として固定すると、条件が変わったときに全員が不利な選択をしたままになります。観点を渡して、その時点でご自身に合うものを選べる状態にしておきます。

選んだサービスは、この回の課題を出すときに一緒に書いてください。同じサービスの環境で見ないと、詰まったときに再現できず、講評ができません。迷ったら、ゼミで使っている Claude と同じ提供元の Claude API にすると、契約と使用量の管理画面が1つにまとまります。

03

API キー：パスワードと同じ扱いをする

API キーは、そのサービスに「自分として」アクセスするための長い文字列です。これを付けて要求を送ると、サービスは「この人からの要求」と判断し、使った分をその人に請求します。

用語

API キー
サービスが発行する、本人確認のための長い文字列。sk-ant-…（Claude）、sk-…（OpenAI）、AIza…（Gemini）のような決まった文字で始まることが多いです（形式は変わることがあります）。
.env
API キーのような秘密の文字列を書いておくファイル。アプリのフォルダの直下に置きます。名前は「環境（environment）」の略です。
環境変数
プログラムの外側から渡す設定値。.env に書いた内容は、起動時に環境変数として読み込まれ、サーバー側のプログラムから process.env.ANTHROPIC_API_KEY のような名前で取り出せます。
.gitignore
共有の場所に上げないファイルの名前を書いておく一覧。ここに .env を書いておくと、コードを共有するときに .env だけが除かれます。
絶対にやってはいけないこと（3つ）
① 画面側のコード（HTML や JavaScript）に書く
② GitHub などコードを共有する場所に上げる
③ スクリーンショットに写ったまま提出する・掲示板に貼る

なぜ画面側に書いてはいけないのか：ブラウザで動くコードは、開発者ツールを開けば誰でも読めます。キーが読まれると、他人がご自身の請求でそのサービスを使い放題になります。キーは「使うと請求が来るパスワード」であって、設定値ではありません。

なぜスクリーンショットまで気にするのか：管理画面でキーを作った直後の画面や、.env を開いた画面をそのまま撮ると、キーの全文が写ります。掲示板や提出物に貼った時点で、見た人全員がそのキーを使えます。写ってしまったら、貼り直すのではなく、管理画面でそのキーを無効化して作り直します。

キーの置き方（この順で）

  1. 1

    アプリのフォルダの直下に .gitignore があるか確認し、無ければ作って .env の1行を書く

    なぜ先に .gitignore か：.env を先に作ると、確認する前に共有の場所へ上がる事故が起きます。上げない設定を先に済ませてからキーを置きます。

  2. 2

    .env を作り、ANTHROPIC_API_KEY=ここに発行したキーを貼る の形で1行書く

    = の前がプログラムから呼ぶときの名前、後ろが発行したキーです。引用符も空白も付けません。

  3. 3

    サーバー側のプログラムからだけ読む

    画面側からは読めないのが正しい状態です。

サービス.env に書く名前（例）公式の説明で確認するもの
Claude APIANTHROPIC_API_KEYキーの発行場所・モデル名・上限設定の場所
OpenAI APIOPENAI_API_KEY同上
Gemini APIGEMINI_API_KEY同上

表は横にスクロールできます

名前はご自身で決めてもよいのですが、上の名前にしておくと、Claude Code が公式の書き方どおりのコードを作りやすくなります（各社の公式ライブラリが、この名前の環境変数を自動で読む作りになっています）。

Claude Code に .env と .gitignore を用意させる指示の型です。そのまま貼って送ります。

APIキーを安全に置く準備をしてください。まだAIは呼びません。
1. アプリのフォルダ直下に .gitignore が無ければ作り、.env と node_modules の2行を入れてください（あれば追記）
2. .env.example というファイルを作り、ANTHROPIC_API_KEY= の1行だけ書いてください（値は空のまま）
3. .env そのものは作らないでください。私が自分で作ります
完成条件：.gitignore に .env が入っていること。.env.example があること。

なぜ .env は自分で作るのか：キーの文字列を Claude Code の入力欄に貼ると、やり取りの記録に残ります。キーはご自身の手でファイルに貼り、AI には「.env から読む」とだけ伝えます。

04

各サービスでキーを発行する

3つとも「ログイン → API キーの画面 → 作成 → 表示されたキーをその場で .env に貼る」の流れです。キーは作った直後にしか全文が表示されないサービスが多いです。画面を閉じる前に .env に貼り、貼れたことを確認してから閉じます。選んだサービスの節だけ読めば足ります。

支払い方法の登録を求められることがあります。登録するときは、同じ画面で上限設定（「AI 機能を入れる」の手順6）まで一緒に済ませます。登録だけして上限を置かないまま作り始めないでください。

4-1. Claude API（Anthropic）

  1. 1

    platform.claude.com を開き、Google アカウントかメールアドレスでログインする

    なぜ：API キーはアカウントに紐づきます。ゼミで使っている Claude のアカウントと同じものでログインすると、契約と使用量を1つの画面で見られます。

  2. 2

    「使用クレジットを購入して開始する」が出たら、ここでは買わず「今はスキップ」

    なぜ：キーを作って .env に置く前に払うと、置き場の確認が後回しになります。買うのは経路が通ってからで間に合います。左のメニュー「組織の設定」→「API キー」を開きます。

  3. 3

    「キーを作成」を押し、名前と有効期限を決めて「キーを作成」

    途中で「ID 連携を使用すれば、API キーは不要です」という案内が出たら「API キーで続ける」を選びます（ID 連携はクラウド上で動かす場合の仕組みで、ご自身の PC で動かすアプリには使いません）。キーの全文が1回だけ表示されるので、その場で .env に貼ります。

  4. 4

    「請求」の画面でクレジットを購入する

    Claude API は前払いで、買ったクレジットの範囲でしか使えません。なぜここが上限設定を兼ねるのか：前払いの残高が上限そのものになります。作りを間違えて何度も呼ばれても、残高が尽きたところで止まります。最初は少額で十分です。金額の選択肢は変わることがあります。

4-2. OpenAI API（OpenAI）

  1. 1

    platform.openai.com を開き、ログインする

    ChatGPT を使っているアカウントでログインできますが、ChatGPT の有料プランと API の契約は別で、API は使った分だけの支払いになります。なぜ確認するのか：ChatGPT の月額を払っていれば API も使えると思って作り始め、認証エラーで止まる人が多いためです。

  2. 2

    左のメニュー「API Keys」→ 右上の「Create new secret key」

    名前を付け、Permissions は「All」のまま「Create secret key」を押します。キーの全文が1回だけ表示されるので、その場で .env に貼ります。

  3. 3

    「Settings」→「Billing」で支払い方法を登録する

    画面に「API credits are separate from ChatGPT」（API のクレジットは ChatGPT とは別）と書いてあるとおり、ChatGPT の契約とは別に、ここで API 用の残高を入れます。

  4. 4

    「Billing」の「Usage limits」で月あたりの上限を設定する

    支払い方法の登録後に設定できるようになります。「Limits」の画面には、1分あたりに送れる回数（レート制限）と、購入額に応じた段階（Tier）が出ます。

4-3. Gemini API（Google）

  1. 1

    aistudio.google.com を開き、Google アカウントでログインする

    左のメニューに「API キー」があります。

  2. 2

    右上の「API キーを作成」を押し、名前とプロジェクトを決めて「キーを作成」

    初めてなら用意されている「Default Gemini Project」のままで構いません。なぜプロジェクトを聞かれるのか：Google はキーや使用量を「プロジェクト」という単位で管理します。アプリ1つに1プロジェクトが基本ですが、まずは既定のもので進めて差し支えありません。表示されたキーはその場で .env に貼ります。一覧に戻ると、作ったキーは末尾の数文字だけが表示されます。

  3. 3

    左のメニュー「課金」で、支払い方法の設定を確認する

    Gemini API は支払い方法を設定しなくても無料枠の範囲で使い始められます（範囲は変わることがあります。「レート制限」の画面で確認できます）。設定するときは、同時に上限も置きます。2026年9月24日時点で、新しく始める人に Google が勧めているモデルは gemini-3.5-flash-lite です（無料枠で、講師のプロジェクトでは1日500回）。gemini-2.5-flash などの 2.5 系は以前から使っていた人だけのものになり、新しく始める人が呼ぶと 404 で止まります。

  4. 4

    「使用量」の画面で、要求の回数とエラーの回数を見る

    AI 機能を入れたあと、この画面を1日1回は見る習慣を付けてください。なぜ：作りを間違えて何度も呼ばれている場合、ここの回数が想定と桁違いになります。請求が来てから気づくのでは遅いためです。

用語

Google Cloud のプロジェクト
Google のサービスで、キーや使用量や請求をまとめる単位。Gemini のキーはどれかのプロジェクトに属します。
レート制限
短い時間に送れる要求の回数の上限。無料枠では1分あたりの回数が少なく設定されています。超えると一時的にエラーになります。
前払い（クレジット）
先に金額を入れておき、その範囲で使う方式。残高が尽きると呼び出しが止まるので、上限の役目を兼ねます。

05

AI 機能を入れる：経路を先に通してから、中身を差し替える

ここでやるのは「自分のアプリのサーバー側から AI のサービスに文章を送り、返ってきた文章を画面に出す」ことです。次の順番を崩さないでください。最初に、いまの画面に動きとサーバーを足して土台を作り（5-1）、そのうえで経路を通して AI に差し替えます（5-2）。

5-1. まず、いまの画面に動きとサーバーを足す

いまのアプリは、app/ の中の HTML と CSS だけでできていて、ボタンを押しても何も起きません（見た目だけの画面＝モック）。AI のサービスを呼ぶには、この画面に次の2つを足します。

  1. ボタンが押されたことを受け取って、画面を書き換えたり、要求を送ったりする部分（画面側の JavaScript）
  2. その要求を受け取って、外部のサービスを呼ぶ部分（サーバー側のプログラム）

アプリは「見た目 → 動き → 裏側」の順に1段ずつ足して作ります。見た目はもうできているので、ここで足すのは動きと裏側だけです。なぜ1段ずつか：一度に全部を作らせると、うまくいかないときに、見た目・動き・裏側のどこが原因か分かりません。1段足すたびに確かめておけば、先に調べるのは最後に足した1段で済みます。

なぜ画面を作り直さないのか：いまある HTML と CSS は、ご自身で見て決めた配置と見た目そのものです。作り直させると配置も文言も変わり、確かめ直しになります。足すのは動きと処理だけで、画面のファイルは土台としてそのまま使います。仕様書の「使う技術」で、HTML をそのまま使わない構成（React など）を選んだ場合は、いまの画面の配置・文言・色・余白を変えずに、その構成の書き方へ移させます。

用語

モック
見た目だけを作った画面。動きや保存の仕組みは入っていません。
Node.js
JavaScript をブラウザの外（PC の上）で動かすための土台のソフト。サーバー側のプログラムを動かすのに使います。
localhost
自分の PC 自身を指す名前。http://localhost:3000 は「自分の PC の中で動いているサーバーの 3000 番の入口」の意味です。インターネットには公開されていません。
ターミナル
文字で命令（コマンド）を打ち込み、結果を文字で受け取る画面。

手順A：サーバーを立てて、いまの画面をそのまま出す

  1. 1

    Node.js が入っているかを Claude Code に聞く

入れる AI 機能は1つだけ

型ごとの例：要約（変換型）／記録の振り返り・傾向の指摘（記録型）／やり取りの続きを返す（相談型）。

なぜ1つだけなのか：AI 機能は「動くかどうか」より「出力が期待どおりか」の調整に時間がかかります。2つ以上入れると、どちらも中途半端なまま残ります。1つが期待どおりに動いてから、次を足します。

出力が毎回変わることへの対処

  1. 出力の形式を指定します。「3行以内」「見出しを付けない」「箇条書き3つ」のように、指示文に形を書きます。形式が毎回違うと、画面の決まった場所に入れられず表示が崩れます
  2. 形式が守られなかったときの表示を用意します。長すぎたら途中で切る、空なら「結果を作れませんでした」と出す、のように決めておきます
  3. 同じ入力でも毎回少し違う文章が返ることを前提にします。「正解と一字一句同じか」で確認するのではなく、「形式が守られているか」「内容が入力に基づいているか」で確認します

AI に送ってよい情報の実物確認

要件定義のときに確認した「社外に出せない情報」を、実際に送る直前にもう一度確認します。なぜ2度確認するのか：要件定義の時点では紙の上で決めただけで、外に出る処理はまだ1つも無かったからです。実際にご自身の PC の外へデータが出るのは、この回が最初です。それまでに保存した項目が、企画時の想定より増えていることも多いです。送る内容を Claude Code に一覧させて（「AI に送っている項目を全部挙げてください」）、目で確認します。

06

データの持ち方：4つの置き場と、消える条件

ここまでのアプリは、データを画面の中に持っているだけで、再読み込みすると消えます。AI 機能が動いたら、次は「このデータをどこに置いておくか」をご自身で決めます。置き場によって、消える条件と、どこから見えるかと、設定の手間が違います。

用語

消える条件
その置き場に入れたデータが無くなる操作や状況。置き場を選ぶときの最初の観点です。
永続化
ブラウザを閉じても、PC を再起動しても残るように保存すること。「画面の中に持っている」状態は永続化されていません。

6-1. ブラウザの中に持つ（localStorage）

ブラウザには、サイトごとに小さなデータを保存しておく領域があり、その1つが localStorage です。JavaScript から「名前」と「文字列」の組で読み書きでき、ブラウザを閉じても残ります。サーバーが無くても動くので、画面側だけで完結します。

用語

localStorage
ブラウザがサイトごとに持っている保存領域。名前と文字列の組を保存します。容量は数 MB 程度で、同じ PC の同じブラウザからだけ読めます。
キャッシュ
表示を速くするために、ブラウザが画像やファイルの写しを一時的に持っておく仕組み。いつ消されてもよい前提のものなので、データの保存には使いません。localStorage はキャッシュとは別の、消されない前提の領域です。
どこにあるか
自分の PC の、そのブラウザの中
消える条件
ブラウザの「閲覧履歴データの削除」でサイトデータを消したとき。別のブラウザ・別の PC・シークレットウィンドウでは最初から見えません
設定の手間
ゼロ。Claude Code に「localStorage に保存して」と言えば動きます
向いている場面
試作／表示の設定（並び順・テーマ）／PC 1台・ブラウザ1つで自分だけが使う小さな記録

なぜ本番の記録には向かないのか：「履歴を削除」の操作で、貯めた記録がまとめて消えます。使う人はそれが記録の削除だとは思っていません。また、スマホから見たいと思ったときに、PC のブラウザの中にあるデータは取り出せません。

記録の保存先を localStorage にしてください。
保存する項目は docs/spec.md の「扱うデータ」のとおりです。
完成条件：記録を1件登録してブラウザを再読み込みしても残っていること。開発者ツールの「アプリケーション」→「ローカルストレージ」に保存した内容が見えること。

6-2. 自分の PC のファイルに持つ（JSON ファイル／SQLite）

サーバー側のプログラムが、アプリのフォルダの中のファイルにデータを読み書きします。ファイルの形は、JSON ファイル1つ（data.json）か、SQLite のファイル1つ（data.db）です。

用語

SQLite
データを1つのファイルに表の形で保存する仕組み。検索や並べ替えを SQL という決まった書き方で頼めます。別のプログラムを起動しておく必要がありません。
SQL
データベースに「この条件の行を取り出して」「この行を書き換えて」と頼むための、決まった書き方の文。
バックアップ
データの写しを別の場所に取っておくこと。ファイルに持っている場合は、そのファイルをコピーするだけで済みます。
どこにあるか
自分の PC の、アプリのフォルダの中（data/ などに置く）
消える条件
そのファイルやフォルダを消したとき／PC が壊れたとき／アプリをインターネット上のサービスに公開した場合、置き直すたびにファイルが初期状態に戻ることが多い
設定の手間
少ない。Node.js の標準機能か、SQLite の部品を1つ入れるだけ
向いている場面
自分の PC だけで使うアプリ／中身をファイルとして開いて確かめたい／バックアップをコピーで済ませたい

なぜ公開すると消えるのか：アプリを動かしてくれる公開用のサービスの多くは、コードを置き直す（デプロイする）たびに、動かす場所をまっさらな状態から作り直します。その中に作ったファイルは、次の置き直しで無くなります。外からも使いたいアプリのデータは、アプリ本体とは別の場所（次の 6-3）に置く必要があります。

JSON ファイルと SQLite のどちらか：件数が少なく項目が単純なら JSON ファイルで足ります。件数が増えて「先月の分だけ」「金額の多い順」のような絞り込みや並べ替えを頻繁にするなら SQLite です。あとで 6-3 のデータベースに移す予定があるなら、最初から SQLite にしておくと、書き方がそのまま使えます。

記録の保存先を、アプリのフォルダ内の SQLite ファイル（data/app.db）にしてください。
保存・読み出しの処理はサーバー側の1つのファイルにまとめ、画面側からは自分のサーバーを呼ぶだけにしてください。
.gitignore に data/ を追加してください。
完成条件：記録を1件登録して、開発サーバーを止めて起動し直しても残っていること。

なぜ data/ を .gitignore に入れるのか：記録の中身はご自身の生活や仕事のデータで、コードと一緒に共有する場所へ上げるものではないからです。

6-3. インターネット上のデータベースに持つ（Turso）

データベースは、データを表の形で保存し、検索・並べ替え・書き換えを専門に担当するプログラムです。Turso は、6-2 で使った SQLite をインターネット上で動かしてくれるサービスで、自分のサーバーからは接続用の URL とトークンを使ってつなぎます。

用語

データベース（DB）
データを表の形で保存し、検索・並べ替え・書き換えを担当する専用のプログラム。アプリ本体とは別の場所に置けます。
Turso
SQLite をインターネット上のサービスとして提供しているもの。手元の SQLite と同じ SQL がそのまま使えます。
接続情報
データベースにつなぐための「場所（URL）」と「本人確認のトークン」。API キーと同じく .env に置き、サーバー側からだけ使います。
デプロイ
作ったアプリを、インターネット上の公開用のサービスに置いて動かすこと。
どこにあるか
Turso のサーバー（自分の PC の外）
消える条件
Turso の管理画面でデータベースを消したとき／契約が止まったとき。アプリを置き直しても消えません。PC を替えても同じデータを見られます
設定の手間
中くらい。Turso のアカウント作成 → データベース作成 → 接続情報を .env へ → サーバー側の接続先を変更
向いている場面
アプリを公開してスマホからも使う／PC を替えてもデータを引き継ぐ／件数が増える見込み

なぜ Turso なのか（ほかの選択肢と、なぜ今回それを選ばないか）

  • 手元の SQLite と同じ SQL がそのまま使えます。6-2 で SQLite にしておけば、変えるのは接続先の数行だけで、保存・読み出しの処理は書き直さなくて済みます
  • Supabase や Firebase のような、画面側から直接データベースにつなげる作りのサービスもあります。便利ですが、アクセス制限の設定を1つ誤ると、データが誰からでも読める状態になります。このゼミでは「データベースにつなぐのはサーバー側だけ」に統一し、その形が自然に取れる Turso にします
  • 無料で使える範囲がありますが、内容は変わることがあります。最新は Turso の公式ページでご確認ください

    作ったデータベースの名前を押して「Overview」を開き、「Connect」の枠の接続用 URL（Database URL）をコピーして .env に貼る

  4. 4

    同じ枠の「Create Token」を押し、有効期限と権限（Read & Write）を選んで「Create Token」

    表示されたトークンを .env に貼ります。トークンは API キーと同じ扱いです。なぜトークンか：URL を知っているだけでは接続できないようにするためです。URL とトークンの両方が揃って初めてつながります。

    .env に TURSO_DATABASE_URL=ここに接続用のURLを貼る と TURSO_AUTH_TOKEN=ここにトークンを貼る の2行を足す

    名前は例です。公式の案内に合わせます。

    Claude Code に、サーバー側の接続先を手元の SQLite から Turso に切り替えさせる

    下の指示の型を貼ります。

接続情報は .env の TURSO_DATABASE_URL と TURSO_AUTH_TOKEN から読み、サーバー側からだけ使ってください。

完成条件：記録を1件登録して、Turso の管理画面でその行が見えること。開発サーバーを止めて起動し直しても残っていること。

6-4. スプレッドシートに持つ（Google スプレッドシート）

データを Google スプレッドシートの表に持ち、サーバー側から Google の API を通して読み書きします。1行が1件、1行目が項目名という形にします。

用語

Google スプレッドシート
Google が提供している、ブラウザで使う表計算のサービス。Excel と同じような表を、インターネット上に持ちます。
サービスアカウント
人ではなくプログラムが Google のサービスを使うための専用アカウント。Google Cloud の管理画面で作り、認証用のファイル（JSON）を受け取ります。このファイルも API キーと同じ扱いで、共有の場所に上げません。
CSV
表の中身をカンマ区切りの文字で書き出したファイル。スプレッドシートや Excel で開けます。
どこにあるか
Google のサーバー（自分の Google ドライブの中）
消える条件
シートを消したとき／サービスアカウントとの共有を外したとき／列の並びや項目名を手で変えたとき（アプリが読めなくなります）
設定の手間
多い。Google Cloud でプロジェクトとサービスアカウントを作る → 認証用のファイルを受け取る → シートをそのアカウントに共有する → サーバー側で API を呼ぶ
向いている場面
一覧を人が眺めて手で直したい／すでにスプレッドシートで管理している作業の続き／家族や同僚と同じ表を見たい

なぜスプレッドシートが選ばれるのか：アプリを作る前からスプレッドシートで管理していた作業なら、これまでの表をそのまま使えます。表を眺めて直すのは、専用の画面を作るより速いです。集計やグラフも、スプレッドシート側の機能で済みます。

なぜ本番のデータベースの代わりにはならないのか

  • 読み書きのたびに Google の API へ通信するので、1回の操作に時間がかかります（体感で分かる程度）
  • 短時間に何度も書き込むと回数の上限に当たります
  • 人が表を直接編集できるのが利点でもあり、列を1つ動かしただけでアプリが読めなくなる弱点でもあります
簡単な代わり：記録の保存先は 6-2 か 6-3 にしておき、「CSV で書き出す」ボタンだけを付けます。書き出した CSV をスプレッドシートに取り込めば、眺める・直す・集計するはスプレッドシートでできます。API の設定が要らないので、まずはこの形で足りるかを考えてみてください。 
記録の保存先を Google スプレッドシートにしてください。
シートの ID は .env の SHEET_ID から、サービスアカウントの認証ファイルの場所は .env の GOOGLE_APPLICATION_CREDENTIALS から読み、サーバー側からだけ使ってください。
1行目を項目名（docs/spec.md の「扱うデータ」の項目名）、2行目以降を1件1行にしてください。
完成条件：アプリで1件登録すると、シートに1行増えること。シートで直した内容がアプリの一覧に反映されること。

6-5. 4つの比較と、選び方

置き場どこにあるか消える条件設定の手間向いている場面
ブラウザの中（localStorage）自分の PC のブラウザ履歴削除／別ブラウザ・別 PC では見えないゼロ試作・設定値・PC 1台で自分だけ
PC のファイル（JSON／SQLite）アプリのフォルダフォルダ削除／PC 故障／公開先で置き直すと初期化少ない自分の PC だけで使う
データベース（Turso）インターネット上管理画面で削除／契約停止中くらい公開してスマホからも使う・PC を替える
スプレッドシートGoogle ドライブシート削除／共有解除／列の手直し多い表を人が眺めて直す・共有

表は横にスクロールできます

選び方：まず「誰が、どこから使うか」で決めます。

  • 自分の PC だけで使う → PC のファイル。SQLite にしておけば、あとで Turso に移せます
  • 公開して外からも使う、PC を替えても続ける → Turso
  • 表を人が直接眺めて直す、家族と共有する → スプレッドシート（まずは CSV 書き出しで足りないかを考えます）
  • 試作や、並び順のような表示の設定だけ → localStorage
保存の処理は、サーバー側の1つのファイルにまとめておきます。画面側は「自分のサーバーに頼む」だけにし、置き場の違いはサーバー側のそのファイルの中だけに閉じ込めます。 なぜ：置き場を変えるとき、直す場所が1つで済みます。画面側にまで保存の処理が散らばっていると、置き場を変えるたびにアプリ全体を作り直すことになります。

決めたら docs/spec.md の「使う技術」の「保存の仕組み」の行を書き換えます（Claude Code に「docs/spec.md の保存の仕組みを Turso に書き換えてください」と指示すれば済みます）。なぜ：仕様書と実物がずれたままだと、次に Claude Code に指示したとき、古い保存先の前提でコードが作られます。

Pitfalls

よくあるつまずきと対処

詰まったら、Home の「分からないことが出てきたらこの順番で」の順（スクショを撮って AI に聞く → ゼミ掲示板）で進めてください。スクショを撮るときは、キーが写っていないかを先に見ます。

キーが漏れた（画面側に書いた・共有に上げた・スクショに写した）

他人がご自身の請求で使い放題になります。

対処：貼り直さず、管理画面でそのキーを無効化して作り直します。.gitignore を先に置く順番に戻します。

課金が膨らんでいる

再描画のたびに呼ぶ作りや連打で、回数が桁違いになっています。

対処：上限設定を先に確認。「ボタンを押したときだけ呼ぶ」「押している間は押せなくする」を指示します。使用量の画面を毎日見ます。

経路を先に通す手順を飛ばした

動かないとき、原因が経路か AI かの2つあって抜けられません。

対処：いったん「テスト応答です」を返す状態に戻して経路を確かめ、通ってから差し替え直します。

契約・支払い登録で止まる

この回の作業に入れません。

対処：契約〜キーの発行は LIVE講義の前に済ませておきます。詰まったらスクショ（キーは伏せる）を撮って AI に聞く → ゼミ掲示板の順で。

ChatGPT の有料プランで API も使えると思っていた

認証エラーで止まります。

対処：API は別契約です。OpenAI Platform の「Billing」で API 用の残高を入れます。

.env を直したのに反映されない

認証エラーが続きます。

対処：開発サーバーを止めて起動し直します（.env は起動時にしか読まれません）。

モデル名のエラーが出る

404 や model not found が返ります。

対処：公式ページで現在の名前を確認し、1箇所にまとめた場所を直します。Gemini で no longer available to new users と出たときは 2.5 系を呼んでいるので、gemini-3.5-flash-lite に直します（2026年9月24日時点）。

出力が毎回違う

表示が崩れる・合っているか確認できません。

対処：形式を指示文で指定し、守られなかったときの表示を用意します。「形式が守られているか」で確認します。

localStorage に本番の記録を貯めてしまった

履歴削除で消える・スマホから見えません。

対処：6-2 か 6-3 に移します。保存の処理がサーバー側の1ファイルにまとまっていれば、直す場所は1つです。

公開したら記録が消えた

公開先で置き直すたびにファイルが初期化されています。

対処：データはアプリ本体と別の場所（Turso）へ移します。

スプレッドシートの列を手で動かしてアプリが読めなくなった

一覧が空になる・エラーになります。

対処：1行目の項目名と列の並びは変えません。変えるなら仕様書を直して Claude Code に読み直させます。

社外に出せない情報を AI に送っていた

情報の持ち出しになります。

対処：送る項目を Claude Code に一覧させて確認します。開発中は架空のデータで進めます。

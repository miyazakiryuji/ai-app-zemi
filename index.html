全7回の流れ

全7回は「決める → 作る → 仕上げる」の3つの段に分かれます。第1〜2回で何を作るかを決め、第3〜6回で見た目 → 動き → 裏側 → テストの順に1段ずつ作り、第7回で落ちないアプリに仕上げます。各回のページは、その回の LIVE講義に合わせて順次公開します。

第1回 ｜ 決めるオリエンテーションゼミの進め方・全7回の流れ・修了要件・開催スケジュール・参加方法のご案内。この回の提出物はありません。この回はこのページです 第2回 ｜ 決める要件定義アプリのフォルダを作って Claude Code で開き、AI と壁打ちして削り込み、使う技術の提案をもらって、仕様書と作る順番をフォルダに残します。作るもの：アプリのフォルダ／docs/spec.md／docs/tasks.md 第3回 ｜ 作るモックを作る（画面を先に作る）仕様書の画面一覧から、見た目だけの画面（モック）を Claude Code に作らせ、ブラウザで開いて「崩れ → テイスト → 細部」の順にブラッシュアップします。作るもの：app/ のモック（HTML と style.css）＋前と後のスクリーンショット＋直した点のメモ 第4回 ｜ 作る画面側を作る ― モックに動きを付ける動きの一覧を作らせ、いちばんよく使う動きから1つずつ、画面の中だけで動くように足して確かめます。入力のチェックと「1件も無いとき・処理中・失敗」の表示も用意します。作るもの：動きの付いた app/＋docs/actions.md＋前と後のスクリーンショット＋つまずきの記録 第5回 ｜ 作るAPI 連携で AI 機能を入れ、データの持ち方を決めるClaude・OpenAI・Gemini のどれかで API キーを発行して安全に置き、経路を先に通してから AI に差し替えます。データの置き場も消える条件から選びます。作るもの：AI 機能が動くアプリ＋上限設定と .gitignore のスクリーンショット＋保存が残る画面と書き換えた docs/spec.md 第6回 ｜ 作るテスト ― 壊れていないことを確かめる仕様書をもとにテストコードを Claude Code に書かせて流し、落ちたら実装側を直します。UI テストと敵対的テストも任せ、テストを流す節目を自分で決めます。作るもの：テストコード一式と結果＋UI・敵対的テストの記録＋README と CLAUDE.md 第7回 ｜ 仕上げるデバッグと卒業制作 ― 落ちないアプリに仕上げる不具合の伝え方・原因の切り分け方を身につけ、Claude Code に再現させて直します。卒業制作で扱う範囲と完成条件を決め、卒業後に自分で続ける手順も持ち帰ります。出すもの：卒業制作（自分専用ツール＋docs/graduation.md）

📗 用語
Claude デスクトップアプリ
PC にインストールして使う Claude の公式アプリ。このゼミでは、この中から Claude Code を呼び出します。
Claude Code
指示を出すと、PC のファイルを実際に作ったり書き換えたりしてくれるツール。画面に答えを表示するだけのチャットとは別のものです。
API
プログラムから、別のサービスの機能を呼び出すための決められた呼び出し方。AI のサービスを自分のアプリから呼ぶときに使います。

この回で押さえたいこと

アーカイブを見返す際の指針にどうぞ。

  1. 人が決めること と AI が担うこと は分かれている

    人が決めるのは、何を作るか／どこまで作るか／出てきたものが正しいかの判断／直す指示。AI が担うのは、コードを書くこと／エラーの原因を推測すること／直すこと。コードが読めなくても進められるのは、この分担があるからです。

  2. 使うのは Claude デスクトップアプリと Claude Code

    Claude Code は、本来はターミナル（文字で PC に命令する画面）から使いますが、このゼミでは Claude デスクトップアプリの中から使います。
    なぜ：最初につまずきやすい箇所を1つ減らすためです。

    数あるツールの中で Claude Code を選んでいるのは、エンジニア以外の方が実際に使って手順を公開している例が多く、調べたときに出てくる情報が幅広いためです。ゼミが終わったあとにご自身で調べて進めるとき、ここが効いてきます。

    画面の名称やボタンの文言は変わることがあります。最新の情報は公式のページをご確認ください。

このゼミの目的

みなさんご自身が「作りたい」と思っているツールやシステムを、自分の手で形にすること。それがこのゼミの目的です。

作るものは、ご自身で決めます教材のサンプルを完成させる場ではありません。ご自身の困りごとを題材にしていただきます（第2回で1つに決めます）。
7回で、動くものを1本つくりきります毎回の課題がそのまま制作の進捗になります。最後に残るのは、実際に自分で使えるシステムです。
終わったあとも、自分で作り続けられる状態へ「アプリができた」で終わりにせず、卒業後にご自身で機能を足していける手順まで持ち帰っていただきます。
🤔 なぜ「自分の題材」なのか他の人が決めた題材は、完成しても使わないままになりがちです。ご自身が毎週やっている手作業が題材なら、動いた日から使うことになります。使い続けるからこそ、次に直したい箇所がご自身で見つかります。ここが、ゼミが終わったあとも続けられるかどうかの分かれ目になります。

このゼミは「学習の場」です

ワークショップ感覚で参加される方が多いので、最初に位置づけをお伝えしておきます。本ゼミはハンズオン形式のワークショップではなく、自習を前提とした学習の場です。

✗ こうではありません（ハンズオン形式のワークショップ）
  • 講師と一緒に、1行ずつコードを書き進めていく
  • 「次はここをクリック」「次はこう入力」と、1ステップずつ全員で操作をなぞる
  • その場で全員が同じ画面・同じ成果物を完成させて終わる
◯ こういう場です（自習を前提とした学習の場）
  • 指定された Lesson を、LIVE の前までに各自で視聴・実践してくる
  • LIVE は、提出課題の公開添削＋自習内容の補足解説＋次の課題の案内が中心
  • 「ここを手元でやってみてください」とお声がけする場面はあります
✅ このゼミならではの点受講生ごとに作るアプリが違い、毎回、自分のアプリを1段ずつ進めます。前の回の課題が終わっていないと次の回で積み上げる土台がないため、毎回の事前課題が実質そのまま制作の進捗になります。手順をなぞって完成させたものは、次にひとりで同じことをやろうとすると再現できません。このゼミが目指しているのは「7回でアプリが1本できた」ではなく、終わったあとも自分で作り続けられることです。

演習サイト Boarding Pass

第2回から、その回で扱った内容の理解度チェックを Boarding Pass で行います。選択式の問題を解くと、その場で採点され、正解と解説が出ます。

入口Boarding Pass を開く（https://quiz-gpassport.vercel.app/）。ログインしたら、メニューの「演習」→ ゼミ一覧から 生成AIアプリ開発ゼミ を選んでください（画面の文言は変わることがあります）。
引っかかったところは演習を解いていて分からないところが出てきたら、下の「分からないことが出てきたらこの順番で」の3ステップ（生成AIに聞く → ゼミ掲示板 → 課題提出フォームの質問欄）で進めてください。Boarding Pass は演習を解くためのサイトで、質問を出す欄はありません。
ログインについてcommmune のアカウントID（プロフィールの「@」の後ろ）と、パスワードで入ります。パスワードは登録のときにご自身で決めたもので、commmune のパスワードとは別です。以前にお名前で登録した方は、そのお名前のままお入りください。新規登録は常時開いてはいないため、LIVE講義中に講師が受付を開きます。
演習の結果は、事前課題の採点対象ではありません。理解度のチェックとしてお使いください。ゼミ終了後は予告なくご覧いただけなくなることがあります。手元に残しておきたい結果は、採点のあとに出る「結果をテキストで保存」から、そのつど保存しておいてください。

分からないことが出てきたらこの順番で

学習中・課題実施中に詰まったら、以下の順で進めてください。1人で抱え込まないことが一番大事です。作り始めるとエラーが必ず出ますが、エラーは失敗ではなく作業の一部です。

  1. まずはスクショして AI に聞く

    エラー画面・つまずいた画面をスクリーンショットで撮り、Claude／ChatGPT／Gemini など普段使っている生成AIに貼り付けて質問してみてください。精度を上げるコツは、「何をしようとしていたか」「どうなる予定だったか」「実際にどうなったか」の3つをスクショに添えることです。
    なぜ：環境まわり・コマンドのエラー・画面の操作迷子は、多くがここで解決します。いちばん早く答えが返ってくる手段から使います。

  2. それでも解決しなければ、ゼミ掲示板へ

    AI に聞いても解決しない／そもそも何を聞けばいいか分からない場合は、DMM 生成AI CAMP 学び放題の上部ナビゲーション「ゼミ掲示板」から投稿してください。他の受講生・運営・講師が回答できます。投稿には、①実現したかったこと ②試したこと（STEP 1 の AI とのやり取りも含めるとなお良い）③つまずきポイント（スクショ歓迎）④環境（OS／ツール／バージョン）を書いてください。

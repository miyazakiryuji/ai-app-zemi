Purpose

このゼミの目的

みなさんご自身が「作りたい」と思っているツールやシステムを、自分の手で形にすること。それがこのゼミの目的です。

作るものは、ご自身で決めます

教材のサンプルを完成させる場ではありません。ご自身の困りごとを題材にしていただきます（第2回で1つに決めます）。

7回で、動くものを1本つくりきります

毎回の課題がそのまま制作の進捗になります。最後に残るのは、実際に自分で使えるシステムです。

終わったあとも、自分で作り続けられる状態へ

「アプリができた」で終わりにせず、卒業後にご自身で機能を足していける手順まで持ち帰っていただきます。

なぜ「自分の題材」なのか：他の人が決めた題材は、完成しても使わないままになりがちです。 ご自身が毎週やっている手作業が題材なら、動いた日から使うことになります。使い続けるからこそ、次に直したい箇所がご自身で見つかります。 ここが、ゼミが終わったあとも続けられるかどうかの分かれ目になります。

Character

このゼミは「学習の場」です

ワークショップ感覚で参加される方が多いので、最初に位置づけをお伝えしておきます。 本ゼミはハンズオン形式のワークショップではなく、自習を前提とした学習の場です。

こうではありません（ハンズオン形式のワークショップ）

  • 講師と一緒に、1行ずつコードを書き進めていく
  • 「次はここをクリック」「次はこう入力」と、1ステップずつ全員で操作をなぞる
  • その場で全員が同じ画面・同じ成果物を完成させて終わる

こういう場です（自習を前提とした学習の場）

  • 指定された Lesson を、LIVE の前までに各自で視聴・実践してくる
  • LIVE は、提出課題の公開添削＋自習内容の補足解説＋次回案内が中心
  • 「ここを手元でやってみてください」とお声がけする場面はあります
このゼミならではの点：受講生ごとに作るアプリが違い、毎回、自分のアプリを1段ずつ進めます。 前の回の課題が終わっていないと次の回で積み上げる土台がないため、毎週の事前課題が実質そのまま制作の進捗になります。 手順をなぞって完成させたものは、次にひとりで同じことをやろうとすると再現できません。 このゼミが目指しているのは「7回でアプリが1本できた」ではなく、終わったあとも自分で作り続けられることです。

When You're Stuck

分からないことが出てきたらこの順番で

学習中・課題実施中に詰まったら、以下の順で進めてください。1人で抱え込まないことが一番大事です。 第3回からはエラーが必ず出ますが、エラーは失敗ではなく作業の一部です。

1STEP 1

まずは
スクショしてAIに聞く

エラー画面・つまずいた画面をスクリーンショットで撮り、Claude／ChatGPT／Gemini など 普段使っている生成AIに貼り付けて質問してみてください。

精度を上げるコツ：

  • 何をしようとしていたか
  • どうなる予定だったか
  • 実際にどうなったか

をスクショに添えて投げる。

2STEP 2

それでも解決しなければ
ゼミ掲示板へ

AIに聞いても解決しない／そもそも何を聞けばいいか分からない場合は、DMM 生成AI CAMP 学び放題 の 上部ナビゲーション 「ゼミ掲示板」 から投稿してください。他の受講生・運営・講師が回答できます。

投稿テンプレ：

  • 実現したかったこと
  • 試したこと（STEP 1 のAIとのやり取りも含めるとなお良い）
  • つまずきポイント（スクショ歓迎）
  • 環境（OS／ツール／バージョン）
「これは聞いていいレベルか…」と迷う必要はありません。1 → 2 の順番で、気軽に出してください。

Key Points

この回で押さえたいこと

アーカイブを見返す際の指針にどうぞ。

  1. 1

    人が決めること と AIが担うこと は分かれている

    人が決めるのは、何を作るか／どこまで作るか／出てきたものが正しいかの判断／直す指示。 AIが担うのは、コードを書くこと／エラーの原因を推測すること／直すこと。 コードが読めなくても進められるのは、この分担があるからです。

  2. 2

    使うのは Claude デスクトップアプリと Claude Code

    Claude Code＝指示を出すと、PCのファイルを実際に作ったり書き換えたりしてくれるツールです。画面に答えを表示するだけのチャットとは別のものです。 本来はターミナル（文字でPCに命令する画面）から使いますが、このゼミでは Claude デスクトップアプリの中から使います。最初につまずきやすい箇所を1つ減らすためです。
    数あるツールの中で Claude Code を選んでいるのは、エンジニア以外の方が実際に使って手順を公開している例が多く、 調べたときに出てくる情報が幅広いためです。ゼミが終わったあとにご自身で調べて進めるとき、ここが効いてきます。
    ※ 画面の名称やボタンの文言は変わることがあります。最新の情報は公式のページをご確認ください。
